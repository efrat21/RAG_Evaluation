# Enterprise Internal Knowledge Assistant — Implementation Plan

A fully local, production-architected RAG system for thousands of employees.
5-layer evaluation, OpenTelemetry distributed tracing, guardrails, Llama via Ollama, and a rich web UI.

---

## Design Decisions (from requirements gathering)

| Decision | Choice |
|---|---|
| **LLM** | Ollama (local) — Llama 3.1 8B for fast generation + Llama 3.3 70B for quality eval |
| **Vector DB** | **Qdrant** — best balance of hybrid search, filtering, Docker simplicity, and open-source maturity |
| **Backend** | Python + LangChain / LangGraph |
| **Evaluation** | RAGAS (retrieval + generation) + custom metrics for Layers 1, 4, 5 |
| **Observability** | OpenTelemetry → Jaeger (traces) + Prometheus (metrics) + Grafana (dashboards) |
| **Guardrails** | LLM-based classifier + regex + a deny-list; implemented as LangChain middleware |
| **Golden Dataset** | Synthetically generated by LLM from ingested docs at startup |
| **UI** | Rich chat (source preview, confidence scores, 👍/👎 feedback) + Grafana-embedded dashboard |
| **Deployment** | Fully local via Docker Compose |

## Stage 2 — Document Ingestion Pipeline

**Goal**: Parse, chunk, embed, and index a diverse enterprise document corpus. Auto-generate the golden dataset.

### Document types supported
- PDFs (policy docs, SOPs, reports) → `PyMuPDF`
- Word / DOCX (HR documents) → `python-docx`
- Markdown / plain text (wikis, READMEs) → native
- HTML pages (intranet exports) → `BeautifulSoup`
- Code files (docstrings, comments) → language-aware chunking

### Pipeline steps

```
Raw File → Parser → Cleaner → Chunker → Embedder → Qdrant Upsert
                 ↓
         Metadata Extractor (source, date, type, department, page)
```

### Chunking strategy
- **Semantic chunking** with `RecursiveCharacterTextSplitter` (768 tokens, 10% overlap)
- **Hierarchical metadata**: document → section → chunk
- Each chunk stores: `doc_id`, `source_path`, `title`, `section`, `chunk_index`, `created_at`, `doc_type`

### Embedding model
- `nomic-embed-text` via Ollama (local, fast, 768-dim)

### Layer 1 — Data Quality Checks (run at ingestion time)

| Check | Implementation |
|---|---|
| **Completeness** | Chunk character count > threshold; warn on empty/stub chunks |
| **Currency** | File `modified_at` vs. freshness policy (configurable TTL) |
| **Parse correctness** | Detect garbled/encoding errors, PDF extraction quality score |
| **Accessibility** | Verify chunk is retrievable from Qdrant after upsert |
| **Duplicate detection** | Cosine similarity check vs. existing vectors |

Metrics exposed to Prometheus:
- `ingestion_docs_total` (counter)
- `ingestion_failed_total` (counter, labeled by error type)
- `chunk_quality_score` (histogram)
- `doc_freshness_days` (gauge)

### Golden Dataset Generation
- After ingestion, run a **LLM-based Q&A generation** pipeline:
  - For each document section, prompt Llama to produce 3–5 Q&A pairs
  - Store as `data/golden_dataset/golden.jsonl`
  - Format: `{question, ground_truth_answer, ground_truth_context, source_doc_id}`
- This dataset drives all RAGAS evaluations in Stage 4

## Stage 3 — RAG Core + Guardrails

**Goal**: The main query pipeline — from user question to grounded, safe answer.

### RAG Pipeline (LangChain / LangGraph)

```
User Query
    │
    ▼
[Guardrail: Input Check]  ◄── Layer: injection, PII, off-topic, toxic
    │
    ▼
[Query Rewriter]           ◄── HyDE or step-back prompting
    │
    ▼
[Hybrid Retriever]         ◄── Dense (Qdrant) + Sparse (BM25) → RRF fusion
    │
    ▼
[Reranker]                 ◄── Cross-encoder reranking (local model)
    │
    ▼
[Context Assembler]        ◄── Builds prompt with citations
    │
    ▼
[LLM: Llama 3.1 8B]       ◄── Ollama
    │
    ▼
[Guardrail: Output Check]  ◄── PII scrubbing, hallucination flag
    │
    ▼
Final Response + Sources
```

### LangGraph State Machine
- **Nodes**: `input_guard`, `query_rewrite`, `retrieve`, `rerank`, `build_prompt`, `generate`, `output_guard`
- **Conditional edges**: if guardrail blocks → return safe refusal message
- **Tool node**: optional web search fallback if no relevant docs found

### Guardrails (all 5 threats)

| Threat | Implementation |
|---|---|
| **Prompt injection** | Regex patterns + LLM classifier (few-shot) + instruction sandboxing in system prompt |
| **PII leakage** | `presidio-analyzer` (Microsoft) — detect & redact SSN, emails, phone, names in output |
| **Off-topic** | Embedding similarity check: query must be within cosine distance of company topic centroids |
| **Toxic content** | LLM-based toxicity classifier (lightweight, runs pre-generation) |
| **Data exfiltration** | Limit context window size; block queries requesting bulk document dumps; rate limiting |

### Distributed Tracing — OpenTelemetry Spans

Every pipeline stage creates a **child span** under the root `rag_request` trace:

| Stage | Span Name | Captured Attributes |
|---|---|---|
| User request | `rag.request` | `request_id`, `timestamp`, `app_version`, `user_role` |
| Input guardrail | `guardrail.input` | `threat_detected`, `threat_type`, `blocked` |
| Query rewrite | `query.rewrite` | `original_query`, `rewritten_query` |
| Retrieval | `retrieval.hybrid` | `query_embedding_time_ms`, `qdrant_duration_ms`, `k`, `bm25_duration_ms` |
| Retrieved context | `retrieval.context` | `doc_ids[]`, `relevance_scores[]`, `rerank_duration_ms` |
| Prompt construction | `prompt.build` | `prompt_version`, `context_size_tokens`, `num_sources` |
| LLM call | `llm.generate` | `model`, `duration_ms`, `prompt_tokens`, `completion_tokens`, `status`, `finish_reason` |
| Output guardrail | `guardrail.output` | `pii_detected`, `redacted_fields[]` |
| Final response | `response.final` | `status`, `eval_score`, `feedback_given` |

Tool executions (if LangGraph tool node runs):

| Stage | Span | Attributes |
|---|---|---|
| Tool execution | `tool.{tool_name}` | `tool_name`, `duration_ms`, `result_status`, `error_msg` |

All spans include: `request_id` (trace root), `session_id`, `latency_ms`.

## Stage 4 — 5-Layer Evaluation Framework

**Goal**: Continuously measure system quality across all five dimensions using the golden dataset.

### Evaluation Architecture

```
Golden Dataset (golden.jsonl)
        │
        ▼
Evaluation Runner (runs on schedule / on-demand)
        │
   ┌────┴────┐
   │  RAGAS  │   ← Layers 2 & 3
   └────┬────┘
        │
  ┌─────┴──────┐
  │ Custom     │   ← Layers 1, 4, 5
  │ Metrics    │
  └─────┬──────┘
        ▼
  Prometheus push  →  Grafana Dashboard
```

---

### Layer 1 — Data Quality

Metrics collected at ingestion time (see Stage 2). Dashboard panel: **Data Health**.

| Metric | RAGAS? | Tool |
|---|---|---|
| Chunk completeness rate | No | Custom |
| Document freshness (% stale) | No | Custom |
| Parse error rate | No | Custom |
| Index coverage (docs retrievable) | No | Custom |

---

### Layer 2 — Retrieval Quality

Run retrieval against golden dataset, compare retrieved docs to `ground_truth_context`.

| Metric | RAGAS? | Notes |
|---|---|---|
| **Precision@k** | No | Fraction of retrieved docs that are relevant |
| **Recall@k** | No | Fraction of relevant docs that were retrieved |
| **MRR** (Mean Reciprocal Rank) | No | Position of first relevant doc |
| **NDCG@k** | No | Graded relevance ranking quality |
| **Context Recall** | ✅ RAGAS | How much of ground truth is in retrieved context |
| **Context Precision** | ✅ RAGAS | Signal-to-noise ratio of retrieved context |

---

### Layer 3 — Generation Quality

Run full pipeline on golden dataset, compare LLM output to `ground_truth_answer`.

| Metric | RAGAS? | Notes |
|---|---|---|
| **Faithfulness** | ✅ RAGAS | Does the answer only use info from retrieved context? |
| **Answer Correctness** | ✅ RAGAS | Semantic similarity to ground truth answer |
| **Answer Relevance** | ✅ RAGAS | Does the answer address the question? |
| **Answer Completeness** | ✅ RAGAS | Are all aspects of the question covered? |
| **Hallucination rate** | Custom | % answers with claims not found in context |

---

### Layer 4 — Application Reliability

Collected continuously from OpenTelemetry spans via Prometheus.

| Metric | Source |
|---|---|
| **P50/P95/P99 latency** (per stage) | OTEL span duration |
| **Availability** (uptime %) | Health check endpoint |
| **Error rate** (by error type) | OTEL span status |
| **Timeout rate** | Span timeout attribute |
| **Guardrail block rate** | Custom counter |
| **LLM call failures** | Span status on `llm.generate` |
| **Tool failure rate** | Span status on `tool.*` |

---

### Layer 5 — Business Outcomes

Collected from user feedback and session analysis.

| Metric | Implementation |
|---|---|
| **User satisfaction (CSAT)** | 👍/👎 buttons in chat UI → stored in SQLite |
| **Task completion rate** | Heuristic: response not followed by "I need more help" |
| **Escalation rate** | % queries ending with "contact HR/IT" fallback message |
| **Cost per successful task** | Token count × estimated compute cost |
| **Session length** | Turns per session before task resolved |

## Stage 5 — Web UI + Observability Dashboard

**Goal**: A polished, rich user-facing chat interface and a live Grafana monitoring dashboard.

### Chat UI (`frontend/index.html`)

Design: **dark mode glassmorphism** — floating chat panel, animated message cards.

Features:
- Rich chat window with **markdown rendering** in LLM responses
- **Source citations panel** — expandable cards showing retrieved document excerpts
- **Confidence score** badge on each response (from RAGAS faithfulness)
- **👍 / 👎 feedback buttons** per response (feeds Layer 5 metrics)
- **Session history** (stored in browser localStorage)
- Animated typing indicator while generating
- Toast notification if guardrail blocks a query ("Query not permitted")

### Monitoring Dashboard (`frontend/dashboard.html`)

An embedded Grafana dashboard showing all 5 layers at a glance:

**Panel layout:**

```
Row 1: [Overall Health Score] [Active Sessions] [Avg Latency P95] [Error Rate]

Row 2 — Layer 1 (Data):
  [Doc Freshness %] [Chunk Quality Score] [Parse Errors/hr] [Index Coverage]

Row 3 — Layer 2 (Retrieval):
  [Context Precision] [Context Recall] [MRR] [NDCG@5]

Row 4 — Layer 3 (Generation):
  [Faithfulness Score] [Answer Correctness] [Relevance] [Hallucination Rate]

Row 5 — Layer 4 (Reliability):
  [Latency by Stage (heatmap)] [Error Rate Timeline] [Guardrail Blocks/hr]

Row 6 — Layer 5 (Business):
  [CSAT %] [Task Completion %] [Escalation Rate] [Cost per Task $]
```

### After each stage
- Stage 1: `docker compose up` runs cleanly; all services healthy; Jaeger and Grafana UIs accessible
- Stage 2: 50+ synthetic docs ingested; golden dataset generated; Qdrant shows vectors; Layer 1 metrics in Prometheus
- Stage 3: End-to-end query returns grounded answer with sources; traces visible in Jaeger; guardrail blocks test injection
- Stage 4: RAGAS scores computed and pushed to Prometheus; all 5 dashboard rows populated
- Stage 5: Chat UI functional; feedback buttons write to DB; dashboard loads with live data

### Integration test
Run a full query through the system using a question from the golden dataset and verify:
1. Jaeger shows a complete trace with all 9 span types
2. Grafana dashboard updates within 15 seconds
3. Response includes correct source citations
4. 👍 button increments CSAT counter in Grafana
